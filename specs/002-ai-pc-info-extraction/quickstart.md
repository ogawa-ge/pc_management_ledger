# Quickstart / 手動検証チェックリスト

## Prerequisites

001-pc-managementの[quickstart.md](../001-pc-management/quickstart.md)と同一のローカル環境セットアップ（Node.js 18+, Python 3.11+, Gemini API Key）を前提とする。加えて、実機検証にはWindows 11 + PowerShellが利用可能な端末が必要（FR-001）。

## 動作確認シナリオ

### シナリオ1: 正常系（貼り付け→自動抽出→登録）

1. `frontend`（`npm run dev`）と`backend/ecs`（`uvicorn src.main:app --reload`）を起動する。
2. PC登録画面（`/pcs/register`）を開く。
3. 表示されたPowerShellコマンドをコピーし、Windows 11端末のPowerShellで実行する。
4. 出力されたJSONを貼り付け欄に貼り付ける。
5. 抽出結果がCPU/メモリ/ストレージ/OS/メーカー/モデルの各欄に自動反映されることを確認する。
6. 任意の項目を手動で書き換える。
7. 登録ボタンを押し、書き換え後の値でPCが登録されることを確認する（一覧画面またはDynamoDBで確認）。

**期待結果**: SC-001（5秒以内反映）、SC-002（抽出精度）、FR-004、FR-005を満たす。

### シナリオ2: 不正なJSON

1. 貼り付け欄に無効なテキスト（例: 途中で切れたJSON）を貼り付けて送信する。

**期待結果**: APIを呼び出さずにエラーメッセージが表示される（FR-006, SC-003）。

### シナリオ3: Gemini API障害（モック）

1. `GEMINI_API_KEY`を一時的に無効な値に差し替える、またはバックエンドのGemini呼び出し部分をモックしてエラーを強制する。
2. 有効なJSONを貼り付けて送信する。

**期待結果**: 3回の自動リトライ後、エラーメッセージが画面に表示され、貼り付け内容は消えずに残っている（FR-007, SC-004）。

### シナリオ4: 抽出対象外項目の未送信確認

1. ブラウザの開発者ツールでネットワークタブを開く。
2. `BiosSerialNumber`を含む出力を貼り付けて送信する。
3. `/api/pcs/parse-specs`へのリクエスト、および（可能であれば）バックエンドのログでGemini APIへの実送信内容を確認する。

**期待結果**: `BiosSerialNumber`の値がGemini API宛のリクエストに含まれていない（FR-008）。

## 手動の動作確認チェックリスト

### 機能確認
- [ ] 貼り付け欄が画面に表示されている（Phase B1）
- [ ] 貼り付け内容（コマンド文字列ではなく実行結果）が抽出APIに送信される（Phase B2）
- [ ] 抽出結果がCPU/メモリ/ストレージ/OS/メーカー/モデルの6項目すべてに反映される（Phase C1）
- [ ] 一部項目が取得不能な場合、該当欄が空欄のまま他の項目は反映される
- [ ] 手動編集後の値が登録データに反映される（自動抽出値で上書きされない）（Phase C2）
- [ ] 不正なJSON貼り付け時にエラーメッセージが表示され、登録が進まない（Phase D1）
- [ ] Gemini API障害時、3回リトライ後にエラーメッセージが表示される（Phase D2）
- [ ] エラー発生時も貼り付け内容がクリアされていない（Phase D2 / データ復旧方針）
- [ ] 抽出中はローディング表示があり、登録ボタンが多重送信を防止する状態になっている

### a11y（アクセシビリティ）確認観点
- [ ] 貼り付け用`<textarea>`に`<label>`が`htmlFor`で明示的に関連付けられている
- [ ] Tabキーのみで「コマンドコピー ボタン→貼り付け欄→登録ボタン」の順に到達できる（不自然な`tabindex`がない）
- [ ] エラーメッセージ領域に`role="alert"`または`aria-live="polite"`が付与され、スクリーンリーダーで読み上げられる
- [ ] ローディング中の登録ボタンに`aria-busy="true"`または同等の状態表現がある
- [ ] エラー表示が色のみに依存していない（アイコンまたはテキストを併用）
- [ ] フォーカスリングがCSSで意図せず消されていない（キーボード操作時に現在位置が視認できる）

### 回帰確認（001-pc-managementの既存フローに影響がないこと）
- [ ] 管理者代理登録画面（001 US3）が本機能の影響を受けず従来通り動作する（002はスコープ外のため変更なし）
- [ ] PC一覧・CSVダウンロード・返却フローに影響がない
