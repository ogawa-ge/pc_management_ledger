# Feature Specification: AI PC情報取得機能

**Feature Branch**: `002-ai-pc-info-extraction`

**Created**: 2026-08-12

**Status**: Draft

**Input**: GitHub Issue #9「AIによるPC情報取得機能が未実装」: AIによるPC情報取得機能が実装されていない。想定機能: 1) ターミナルで実行されたスペック情報の結果を受け取る（PowerShellの `Get-ComputerInfo | Select-Object WindowsProductName, WindowsVersion, TotalPhysicalMemory, BiosSerialNumber, ProcessorName, GPUName | ConvertTo-Json` の実行結果） 2) Gemini等のAI APIを使用して必要なデータ項目のみを抽出・整形 3) 整形されたデータをフォームに反映する。

## Clarifications

### Session 2026-08-12

- Q: Gemini APIの呼び出しが失敗（タイムアウト・API障害・エラーレスポンス）した場合、システムはどう振る舞うべきか？ → A: 最大3回まで自動リトライする。3回失敗した場合はエラー内容を画面に表示し、手動入力を促す。
- Q: 貼り付けられたターミナル出力に含まれるBIOSシリアル番号など、抽出対象外の機微な項目は、Gemini APIに送信する前に除外すべきか？ → A: 除外する。抽出に必要な項目のみをGemini APIに送信する。
- Q: このAI抽出機能は、管理者がユーザーの代理でPCを登録する画面（001-pc-managementのUS3: 代理登録）でも利用できるようにすべきか？ → A: いいえ。一般ユーザーの自己登録画面のみを対象とし、代理登録画面は本機能のスコープ外とする。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - ターミナル出力の貼り付けとAIによる自動抽出 (Priority: P1)

ユーザーはPC登録画面で提示されたPowerShellコマンド（`Get-ComputerInfo` ベース）を自分の端末で実行し、その出力（JSON形式）をフォームに貼り付けることで、Gemini APIが必要な項目のみを自動抽出し、フォームに反映する。

**Why this priority**: 手入力の負担軽減はPC管理台帳アプリの中核的な価値提案であり、これが機能しない限りPC登録機能全体の価値が成立しないため。

**Independent Test**: ターミナル出力（JSON形式）をPC登録画面の入力欄に貼り付けた際に、CPU・メモリ・OSバージョン等の判別可能な項目が自動でフォームに反映されることを確認する。

**Acceptance Scenarios**:

1. **Given** PC登録画面を開いている, **When** 指定されたPowerShellコマンドの実行結果（JSON）を貼り付ける, **Then** Gemini APIにより抽出された項目がフォームの該当欄に自動反映される
2. **Given** 貼り付けた内容の一部の項目が取得元コマンドの出力に含まれていない, **When** 抽出処理を実行する, **Then** 判断可能な項目のみが反映され、取得できなかった項目は空欄のまま手動入力を促す
3. **Given** 貼り付けた内容がJSONとして不正な形式である, **When** 抽出処理を実行する, **Then** エラーメッセージが表示され、登録処理は継続されない
4. **Given** 貼り付けた内容が有効なJSONである, **When** Gemini APIの呼び出しが失敗する, **Then** システムは最大3回まで自動的にリトライし、それでも失敗した場合はエラー内容を画面に表示して手動入力を促す

---

### User Story 2 - 抽出結果の確認・手動修正 (Priority: P2)

ユーザーは自動抽出された内容を登録前に確認し、必要に応じて修正できる。

**Why this priority**: AI抽出の精度に依存せず、最終的に正確なデータが登録されることを保証するため。

**Independent Test**: 自動反映後にフォームの値を編集し、編集後の内容で登録が完了することを確認する。

**Acceptance Scenarios**:

1. **Given** AIによる自動抽出が完了しフォームに値が反映されている, **When** ユーザーがフォームの値を編集する, **Then** 編集後の値で登録できる

---

### Edge Cases

- 貼り付けられた内容が想定外のコマンド出力（`Get-ComputerInfo` 以外の形式）だった場合はどうなるか？
  - 判断できる情報だけを利用する（001-pc-managementの既存方針を踏襲）。
- `Get-ComputerInfo` の出力に含まれない項目（ストレージ容量、メーカー名、モデル名など）はどう扱うか？
  - 未取得として空欄のままにし、ユーザーに手動入力を促す。
- 貼り付け内容が空、またはJSONとして解析不能な場合はどうなるか？
  - エラーメッセージを表示し、登録処理を継続させない。
- Gemini APIの呼び出しが失敗（タイムアウト・API障害・エラーレスポンス）した場合はどうなるか？
  - 最大3回まで自動的にリトライする。3回失敗した場合はエラー内容を画面に表示し、ユーザーに手動入力を促す。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムはPC登録画面において、指定されたPowerShellコマンド（`Get-ComputerInfo` ベース、`WindowsProductName`, `WindowsVersion`, `TotalPhysicalMemory`, `BiosSerialNumber`, `ProcessorName`, `GPUName` を含むJSON出力を生成するコマンド）をクリップボードにコピーする機能を提供しなければならない。
- **FR-002**: システムはユーザーが貼り付けたターミナル出力（JSON文字列）を受け取るための入力欄をPC登録画面に提供しなければならない。
- **FR-003**: システムはGemini APIを使用し、貼り付けられたテキストからCPU、メモリ容量、OSバージョン、メーカー名、モデル名、ストレージ容量のうち判断可能な項目のみを抽出しなければならない。
- **FR-004**: システムは抽出された項目をPC登録フォームの対応するフィールドに自動反映しなければならない。
- **FR-005**: ユーザーは自動反映された値を登録前に手動で編集できなければならない。
- **FR-006**: 貼り付けられた内容がJSONとして解析できない場合、システムはエラーメッセージを表示し、登録処理を継続させてはならない。
- **FR-007**: Gemini API呼び出しが失敗した場合、システムは最大3回まで自動的にリトライしなければならない。3回リトライしても失敗した場合、システムはエラー内容を画面に表示し、ユーザーに手動入力を促さなければならない。
- **FR-008**: システムはGemini APIへ送信するデータから、抽出対象の6項目（CPU、メモリ容量、ストレージ容量、OSバージョン、メーカー名、モデル名）に含まれない項目（BIOSシリアル番号などの識別子を含む）を送信前に除外しなければならない。

### Key Entities *(include if feature involves data)*

- **PC**: 既存の `PC` エンティティ（管理番号、所有者、種別、ステータス、スペック情報）を再利用する。本機能は新規エンティティを追加せず、既存のスペック情報フィールド（CPU、メモリ容量、ストレージ容量、OSバージョン、メーカー名、モデル名）への入力経路を修正・完成させるものである。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーはターミナル出力を貼り付けてから5秒以内に抽出結果がフォームに反映される。
- **SC-002**: Gemini APIによる抽出精度は、CPU・メモリ・ストレージ・OS・メーカー・モデルの6項目中、少なくとも5項目が正確に抽出される割合が95%以上である。
- **SC-003**: 不正な形式の貼り付け内容に対して、100%の確率で適切なエラーメッセージが表示される。
- **SC-004**: Gemini API呼び出しが失敗した場合、3回のリトライ後にエラー内容が画面に表示される割合は100%である。

## Assumptions

- 本機能は既存機能仕様（`specs/001-pc-management/spec.md` の FR-006 V1.0 / FR-007）で定義された「コマンドをクリップボードにコピー → ユーザーが手動でターミナル実行・貼り付け → Gemini APIで抽出 → フォーム反映」というフローの完成・修正を目的とし、V2.0で計画されているターミナルの自動実行・自動入力は本機能のスコープ外とする。
- `Get-ComputerInfo` コマンドの出力に含まれないストレージ容量・メーカー名・モデル名は、取得可能な場合のみ抽出し、取得できない場合は手動入力に委ねる。
- Gemini APIキーは環境変数として既に設定されている（001-pc-managementの前提を継承）。
- 対象OSはWindows 11を想定し、PowerShellが利用可能であることを前提とする。
- 本機能の対象は一般ユーザーによる自己登録画面（001-pc-managementのUS2）のみとし、管理者による代理登録画面（001-pc-managementのUS3）は本機能のスコープ外とする。
