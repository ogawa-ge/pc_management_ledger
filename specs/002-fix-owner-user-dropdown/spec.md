# Feature Specification: PC新規登録時のオーナーユーザー選択修正

**Feature Branch**: `002-fix-owner-user-dropdown`
**Created**: 2026-08-12
**Status**: Draft
**Input**: User description: "Issue #7: PC新規登録時にオーナーユーザープルダウンへUsersテーブルのユーザー一覧を表示する"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 代理登録対象ユーザーの選択 (Priority: P1)

管理者はPC新規登録画面でオーナーユーザーの選択欄を開き、登録済みのユーザー一覧からPCの所有者を選択できる。これにより、管理者はPCを正しいユーザーに紐付けて代理登録できる。

**Why this priority**: Issue #7 の直接の問題であり、オーナーを選べないと管理者によるPC代理登録を完了できないため。

**Independent Test**: 複数のユーザーが登録された状態で管理者がPC新規登録画面を開き、選択欄から任意のユーザーを選択できることを確認する。

**Acceptance Scenarios**:

1. **Given** 複数のユーザーが登録済みで管理者がPC新規登録画面を開いている, **When** オーナーユーザーのプルダウンを開く, **Then** 登録済みのユーザーが選択肢として表示される
2. **Given** ユーザー一覧が表示されている, **When** 管理者がユーザーを1名選択する, **Then** 選択したユーザーが現在のオーナーとして表示され、PC登録に利用できる
3. **Given** ユーザー一覧からユーザーを選択している, **When** PCの新規登録を完了する, **Then** 登録されたPCが選択したユーザーに紐付く

---

### User Story 2 - ユーザー一覧取得失敗時の案内 (Priority: P2)

管理者はユーザー一覧を取得できない場合、選択欄が空欄のままになるのではなく、取得できなかったことを認識できる。これにより、所有者未設定のまま誤登録することを防げる。

**Why this priority**: データ取得の失敗とユーザーが存在しない状態を区別し、誤ったPC登録を防ぐため。

**Independent Test**: ユーザー一覧の取得に失敗する状態でPC新規登録画面を開き、明確なエラー案内と登録操作の制御を確認する。

**Acceptance Scenarios**:

1. **Given** ユーザー一覧を取得できない, **When** 管理者がオーナーユーザーのプルダウンを確認する, **Then** ユーザー一覧を取得できない旨の案内が表示され、空の選択欄だけが表示されない
2. **Given** ユーザー一覧を取得できない, **When** 管理者がPC登録を実行しようとする, **Then** オーナーを確認できない状態での登録が完了しない

---

### Edge Cases

- Usersに登録済みユーザーが存在しない場合、選択欄にはユーザーが存在しない旨を表示し、登録済みユーザーを選択必須とする。
- ユーザー一覧の取得中は、取得完了まで選択欄を操作できない状態とし、取得中であることを表示する。
- ユーザー名などの表示用情報が欠落しているユーザーは、識別可能な代替表示を行い、他ユーザーと区別できるようにする。
- ユーザー一覧の取得後に対象ユーザーがUsersから削除された場合、PC登録前に存在を再確認し、存在しないユーザーへの紐付けを完了させない。
- ユーザーがDynamoDBの1回のscanで返せる件数を超える場合でも、全ページを取得して一覧へ重複なく表示し、各選択肢を一意に識別できるようにする。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システム MUST PC新規登録画面を開いた管理者に対し、登録済みユーザーをオーナーユーザーの選択肢として表示する。
- **FR-002**: システム MUST 表示する各ユーザーを一意に識別できる表示情報を選択肢に含める。
- **FR-003**: 管理者 MUST 表示されたユーザー一覧からオーナーユーザーを1名選択できる。
- **FR-004**: システム MUST 選択されたユーザーをPC新規登録のオーナーとして保持し、登録完了時にそのユーザーとPCを紐付ける。
- **FR-005**: システム MUST ユーザー一覧の取得中であることを表示し、取得完了前のオーナー選択を許可しない。
- **FR-006**: システム MUST ユーザー一覧の取得に失敗した場合、取得失敗を管理者に通知し、オーナー未確認のPC登録を完了させない。
- **FR-007**: システム MUST 登録済みユーザーが0名の場合、ユーザーが存在しないことを表示し、オーナー未設定のPC登録を完了させない。
- **FR-008**: システム MUST 管理者にはUsersに存在する任意のオーナー候補を指定した代理登録を許可し、一般ユーザーには認証主体本人をオーナーとする既存のPC登録だけを許可して、他ユーザーの指定を拒否する。
- **FR-009**: システム MUST 既存のPC登録におけるPC種別、スペック入力、ターミナルコマンド、Geminiスペック解析、管理番号採番、PC保存形式、登録中の二重送信防止、および登録成功後のPC一覧への遷移を変更しない。

### Key Entities

- **User**: PCのオーナー候補となる登録済みユーザー。表示用情報と一意な識別情報を持つ。
- **PC**: 新規登録される資産。選択されたUserをオーナーとして紐付ける。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Usersに一意なuserIdを持つユーザーが2件以上存在する各受け入れテストケースで、管理者向けオーナー選択欄に取得対象の全ユーザーが重複なく表示される。
- **SC-002**: 20〜30件のUsersを用い、ECS APIがreadyで人工的な通信遅延を設定していない受け入れ環境において、ブラウザが `GET /api/users` を開始してからオーナー選択欄が操作可能になるまでを3回計測し、全回30秒以内とする。ECSのcold startと管理者が選択を判断する時間は計測に含めない。
- **SC-003**: 選択したユーザーをオーナーとして登録したPCについて、100%のテストケースで登録後のオーナーが選択内容と一致する。
- **SC-004**: ユーザー一覧の取得失敗またはユーザー0件のケースで、オーナー未設定のPCが100%登録されない。
- **SC-005**: Issue #7 の再現手順を回帰テストとして実行し、Usersの異なる2件以上のuserIdがオーナー選択肢のvalueとして表示され、そのうち任意の1件を選択してPC登録に使用できる。

## Assumptions

- 対象ユーザーは既存のUsersに登録済みのユーザーであり、この機能ではユーザーの新規作成や編集を扱わない。
- オーナー選択機能の利用者は管理者であり、一般ユーザーの自身のPC登録フローは変更対象外とする。
- ユーザーの表示名および一意な識別情報は既存のユーザー情報を利用する。新しいデータ項目の定義は本仕様では行わない。
- 「利用可能なユーザー」はPC登録時の再確認でUsersに存在するオーナー候補を指す。既存モデルに定義されていない有効・無効属性は推測せず、削除済みまたは存在しないユーザーは登録対象外とする。
- PC登録画面、既存の権限管理、PCとユーザーの紐付け機能が利用可能であることを前提とする。
- ユーザー一覧の並び順は既存のユーザー一覧表示ルールに従い、本不具合修正の必須条件には含めない。

## Out of Scope

- Usersへのユーザー追加、削除、編集、権限変更。
- PC新規登録画面以外のユーザー一覧表示の刷新。
- PCのスペック抽出、管理番号採番、返却処理など、Issue #7 と直接関係しない既存機能の変更。
