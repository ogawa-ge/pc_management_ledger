# Feature Specification: PC新規登録時の登録失敗・画面固まり解消

**Feature Branch**: `007-fix-pc-registration`

**Created**: 2026-11-18

**Status**: Completed

**Input**: User description: "GitHub Issue #30: PC新規登録時にECSのUsersテーブル権限不足等で登録が失敗・固まる問題の修正"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 一般ユーザーおよび管理者によるPC新規登録の完了 (Priority: P1)

ログイン済みの一般ユーザーまたは管理者が、PC新規登録画面でPC情報を入力して登録を実行した際、バックエンドの権限エラーで失敗することなく正常に登録が完了し、PC一覧画面に反映されるようにする。

**Why this priority**: PC新規登録は本システムの根幹機能であり、現在登録が一切完了できない状態のため最優先で解消する必要がある。

**Independent Test**: 一般ユーザーまたは管理者でログインし、PC新規登録画面から必須項目を入力して登録を実行した際、エラーにならず登録完了メッセージが表示され、PC一覧画面に新規登録したPCが表示されることで検証可能。

**Acceptance Scenarios**:

1. **Given** 一般ユーザーがログイン済みでPC新規登録画面を開いている状態、**When** 必要なPC情報を入力して登録を実行する、**Then** 認証ユーザー情報の検証が正常に通過し、PCが登録されてPC一覧画面へ遷移・表示される。
2. **Given** 管理者がログイン済みでPC新規登録画面を開いている状態、**When** オーナー候補からオーナーを選択してPC情報を入力し登録を実行する、**Then** 選択したオーナーでPCが登録され、PC一覧画面へ遷移・表示される。

---

### User Story 2 - 管理者向けオーナー候補一覧のコールドスタート対応と登録エラーの明確な表示 (Priority: P2)

バックエンドがコールドスタート中であっても、管理者の代理登録画面でオーナー候補一覧を自動待機により取得できるようにし、万一登録に失敗した場合はECS起動待機表示を確実に閉じたうえで、操作ボタン付近に日本語のエラー内容を一目で認識できるようにする。

**Why this priority**: 画面が固まったまま無反応に見える原因を取り除き、利用者が状況（起動待機中か、エラーか）を即座に判断できるようにするため。

**Independent Test**: コールドスタート中に管理者がPC新規登録画面を開いた際に自動リトライでオーナー候補一覧が取得できること、および登録失敗時（タイムアウト含む）にECS起動待機表示が解除され登録ボタン付近へ日本語のエラーメッセージが表示されることで検証可能。

**Acceptance Scenarios**:

1. **Given** バックエンドがコールドスタート中である、**When** 管理者がPC新規登録画面を開く、**Then** オーナー候補一覧の取得が即座に失敗せず、起動完了まで待機・再試行してオーナー候補を表示する。
2. **Given** PC登録時にエラー（タイムアウト・通信障害・サーバーエラー等）が発生した状態、**When** 登録処理が失敗する、**Then** ECS起動待機表示が確実に解除され、利用者が操作している登録ボタンの直上（視界に入る位置）に、英語の生メッセージではなく状況に応じた日本語のエラーメッセージが視認しやすく表示され、無反応・固まったように見えない。

---

### Edge Cases

- 権限のない一般ユーザーが他人のPCを代理登録しようとした場合は、従来通り拒否されること。
- 必須項目（PC名、OS、CPU、メモリ、ストレージ等）が未入力のまま送信しようとした場合は、入力チェックで案内されること。
- 起動待機が上限時間（タイムアウト）に達した場合でも、ECS起動待機表示が残存して画面操作を塞がないこと。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムのバックエンド処理基盤は、PC登録・返却・オーナー候補一覧取得などの業務処理時に認証ユーザーおよび利用可能なユーザー（オーナー）の存在・権限情報を参照できなければならない。
  - **ユーザー情報（Users）を参照する理由**: PCデータ自体にユーザー詳細情報をコピーするためではなく、①操作者が登録済みの正当なユーザーであるかの本人確認、②操作者のロール（一般ユーザーは自分名義のPCのみ登録可、管理者は他ユーザーの代理登録可）の判定、③指定されたオーナーが利用可能なユーザー（実在するユーザー）であるかの整合性チェック、の3つのセキュリティ・データ整合性確認を行うため。
- **FR-002**: システムは、管理者がPC新規登録画面を開いた際、バックエンドがコールドスタート中であっても自動的に再試行してオーナー候補一覧を取得できなければならない。
- **FR-003**: システムは、PC新規登録の実行が失敗した際（タイムアウト含む）、ECS起動待機表示を確実に解除したうえで、操作中の登録ボタン付近に、HTTPステータス・エラー種別に応じた日本語のエラーメッセージを明確に表示しなければならない（英語の生メッセージは表示しない）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 一般ユーザーおよび管理者のいずれも、PC新規登録画面から1回の操作で100%正常にPC登録を完了し、PC一覧画面で確認できる。
- **SC-002**: バックエンドがコールドスタート中であっても、管理者がPC新規登録画面を開いてから待機・自動再試行によりオーナー候補からオーナーを選択可能になる。
- **SC-003**: 登録エラー発生時、ECS起動待機表示が画面を塞ぐことなく、画面スクロールなしで登録ボタン付近に日本語のエラー内容を確認でき、英語の生メッセージの露出が0件である。

## Assumptions

- 用語定義は [docs/ubiquitous-language.md](file:///c:/Users/hagihara/pc_management_ledger/docs/ubiquitous-language.md)（ユーザー / 管理者 / 一般ユーザー / オーナー / オーナー候補 / 利用可能なユーザー / 代理登録 / コールドスタート / ECS起動待機表示）に準拠する。
- 認証・権限管理に関する既存のロール設計（一般ユーザーは自分名義のみ登録可、管理者はオーナー候補から選択して代理登録可）は変更しない。
- 初回ログインのユーザーは常に一般ユーザーとして作成される。管理者ロールの付与は手動（Users テーブルの `role` 変更）であり、付与手順そのものは本 Issue の対象外とする。管理者の代理登録の実機検証は、管理者アカウントを用意できた場合に実施する。
- 他画面（PC一覧、返却画面など）の仕様変更や無関係なリファクタリングは行わない。
