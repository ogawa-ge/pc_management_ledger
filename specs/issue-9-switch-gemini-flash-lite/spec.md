# Feature Specification: AI抽出モデルの軽量モデルへの切り替え

**Feature Branch**: `issue-9-switch-gemini-flash-lite`

**Created**: 2026-11-25

**Status**: Completed

**Input**: User description: "Issue #9"（GitHub Issue #9「AIによるPC情報取得機能が未実装」の本文「追記（2026-11-25）：本番環境での問題とGeminiモデルの切り替え」）。AWS環境を移行したあとの本番で、AI抽出が「通信エラー」で失敗する。原因は `gemini-3.6-flash` の混雑（503）や応答の遅れ（13〜28秒）により、Lambdaの待ち時間の上限（25秒）を超えていること。AI抽出に使うモデルを `gemini-3.5-flash-lite` に切り替える（ローカル検証で1〜3秒・全項目を正しく抽出、安定版で提供終了日は未発表）。メモリとストレージのGB値は、AIに任せたおおまかな値でよい（単位がGBであればよい）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 本番環境でAI自動抽出が時間内に完了する (Priority: P1)

ユーザー（一般ユーザーの自己登録、管理者の代理登録のいずれも含む）は、本番のPC登録画面でPowerShellの実行結果を貼り付けてAI抽出を実行すると、「通信エラー」にならず、短い待ち時間で抽出結果がフォームに反映される。

**Why this priority**: 現在、本番ではAI抽出がほぼ使えない状態であり、PCスペック登録の自動化という本システムの中核価値（Constitution Layer 2）が提供できていないため。

**Independent Test**: 本番のPC登録画面で、バックエンドが起動済みの状態でPowerShellの実行結果を貼り付けてAI抽出を実行し、通信エラーにならずに各項目がフォームに反映されることを確認する。

**Acceptance Scenarios**:

1. **Given** 本番のPC登録画面を開いており、バックエンドが起動済みである, **When** 指定のPowerShellコマンドの実行結果を貼り付けてAI抽出を実行する, **Then** 通信エラーにならず、判断可能な項目（CPU、メモリ、ストレージ、OS、メーカー、モデル、GPU、PC名）がフォームに反映される
2. **Given** AI抽出を実行した, **When** メモリ容量とストレージ容量が反映される, **Then** 値はGB単位・小数点第1位までの数値で表示される（1GBを何バイトとして数えるかはAIの判断に任せ、おおまかな値でよい）

---

### User Story 2 - 抽出結果の品質が切り替え前と同等である (Priority: P2)

ユーザーは、モデルの切り替え後も、切り替え前と同じ項目を同じ程度の正確さで自動入力してもらえる。

**Why this priority**: 速度の改善と引き換えに抽出できる項目が減ったり誤りが増えたりすると、手入力の負担が戻ってしまうため。

**Independent Test**: 同一のサンプル入力（PowerShellの実行結果）で抽出を行い、全8項目が抽出されること、およびCPU・OS・メーカー・モデル・GPU・PC名が元データと矛盾しないことを確認する（表記の細かな違い、例えば「Microsoft Windows 11 Pro」と「Windows 11 Pro」は問題としない）。

**Acceptance Scenarios**:

1. **Given** 切り替え前に全8項目を抽出できていたサンプル入力がある, **When** 切り替え後に同じ入力で抽出を実行する, **Then** 全8項目が抽出され、CPU・OS・メーカー・モデル・GPU・PC名は元データと矛盾しない値になる

---

### Edge Cases

- AIサービス側が混雑・障害でエラーを返した場合はどうなるか？
  - 既存の動作（002-ai-pc-info-extraction の FR-007）のとおり、エラー内容を表示して手動入力を促す。本機能で変更しない。
- バックエンドが停止中（コールドスタート）の場合はどうなるか？
  - 既存の起動待機表示と再試行（007-fix-pc-registration）のとおり。本機能では変更しない。
- メモリ・ストレージのGB値が、製品のスペック表の値（例: 512GB）とWindowsの表示値（例: 476.9GB）のどちらになるか？
  - どちらでもよい（ユーザー決定、2026-11-25）。単位がGBであることのみを求める。
- 切り替え先のモデルが将来提供終了になった場合はどうなるか？
  - 提供終了の告知を受けて、別のIssueで後継モデルへ切り替える。本機能の範囲外。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、AI抽出に使用するモデルを、本番の待ち時間の上限（25秒）に対して十分短い時間（目安10秒以内）で応答する軽量なモデル（Issue #9 で決定した `gemini-3.5-flash-lite`）に切り替えなければならない。
- **FR-002**: システムは、切り替え後も既存の抽出項目（CPU、メモリ容量、ストレージ容量、OS、メーカー名、モデル名、GPU、PC名）をすべて抽出対象としなければならない。
- **FR-003**: システムは、メモリ容量とストレージ容量をGB単位・小数点第1位までで返さなければならない。バイトからGBへの換算方法（1000単位か1024単位か）は指定しない。
- **FR-004**: 本機能は、AI抽出の入出力の形式、エラー時の表示・リトライ、機微な項目の除外（002-ai-pc-info-extraction の FR-006〜FR-008）、および画面の動作を変更してはならない。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 本番で、バックエンドが起動済みの状態でAI抽出を5回連続で実行し、5回とも通信エラーにならず、10秒以内に抽出結果がフォームに反映される。
- **SC-002**: 同一のサンプル入力に対して、全8項目が抽出され、CPU・OS・メーカー・モデル・GPU・PC名は元データと矛盾しない。
- **SC-003**: メモリ容量とストレージ容量は、すべての抽出結果でGB単位・小数点第1位までの数値として表示される。

## Assumptions

- 切り替え先のモデル `gemini-3.5-flash-lite` は安定版で、提供終了日は未発表である（Google公式の Gemini deprecations ページ、2026-11-25時点）。
- Gemini APIキーは、会社のGoogle Workspaceアカウントで発行した無料枠のキーに切り替え済みであり、このキーで `gemini-3.5-flash-lite` を利用できることをローカルで確認済みである（Secrets Manager の `GeminiApiKey`）。
- 現在は試験的に運用している段階であり、無料枠の利用回数の上限とデータの取り扱い条件で問題ないものとする。
- Lambdaの待ち時間の上限（25秒）、ECS側のリトライ設計、非同期化などの構成の見直しは本機能の範囲外とする。
- 本番への反映には、ECSの再デプロイが必要である（デプロイの手順・実施者はチームの運用に従う）。
- 抽出対象の項目・プロンプトの内容は、既存の 002-ai-pc-info-extraction（T044 まで）の実装を引き継ぐ。
